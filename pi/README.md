# pi harness config

Linked into `~/.pi/agent` by `install.sh`. Re-running the installer is safe and
idempotent.

## Bootstrapping a new machine

```bash
git clone <this repo> ~/personal/dotfiles
cd ~/personal/dotfiles && ./install.sh
pi          # installs every package in settings.json on first run
```

`settings.json` carries the `packages` list, and pi installs anything missing
into `~/.pi/agent/npm` during resource loading — before the first model call.
There is no separate `pi install` step.

Then, per the installer's closing notes:

1. Create `pi/extensions/pi-automode/config.json` (see below) and re-run
   `install.sh`.
2. `pi` → `/login` for each provider: `anthropic`, `openai-codex`. Local
   `llama-server` needs no credential.
3. Authorize the Linear MCP server (OAuth, on first use).

## Layout

| Repo path | Links to | Purpose |
| --- | --- | --- |
| `settings.json` | `~/.pi/agent/settings.json` | packages, provider/model defaults, statusline, theme |
| `CLAUDE.md` | `~/.pi/agent/CLAUDE.md` | global agent instructions |
| `APPEND_SYSTEM.md` | `~/.pi/agent/APPEND_SYSTEM.md` | appended to the system prompt |
| `model-router.json` | `~/.pi/agent/model-router.json` | `@yeliu84/pi-model-router` tiers |
| `prompts/handoff.md` | `~/.pi/agent/prompts/handoff.md` | prompt template |
| `extensions/tmux-status.ts` | `~/.pi/agent/extensions/tmux-status.ts` | tmux window state |
| `extensions/guardrails.json` | `~/.pi/agent/extensions/guardrails.json` | `@aliou/pi-guardrails` policy |
| `../mcp/mcp.json` | `~/.config/mcp/mcp.json` | MCP servers |

`settings.json` and `extensions/guardrails.json` are symlinked, so pi and the
guardrails settings UI write **through to this repo**. That is intentional —
`pi install X` on any machine shows up as a diff here. It also means pi's
`lastChangelogVersion` bump dirties the repo after a pi upgrade.

## Deliberately not tracked

| Path | Why |
| --- | --- |
| `~/.pi/agent/auth.json` | provider credentials |
| `~/.pi/agent/models-store.json` | provider model catalogs, mode 600 |
| `~/.pi/agent/trust.json` | absolute per-machine project-trust paths |
| `~/.pi/agent/mcp-cache.json` | cache |
| `~/.pi/agent/sessions/`, `statusline-transcripts/` | run history |
| `~/.pi/agent/npm/` | installed packages; rebuilt from `settings.json` |
| `~/.pi/agent/bin/fd` | platform binary, pi-managed |
| `~/.pi/agent/skills/` | symlinks into `~/.agents/skills`, managed by a separate skill tool with its own `.skill-lock.json` |

## pi-automode config is a manual step

`pi-automode` deterministically hard-denies agent writes to its own
configuration — including this repo's copy — so it cannot be generated by an
agent and is created by hand. `install.sh` links it only if present and
otherwise prints a reminder.

Create `pi/extensions/pi-automode/config.json`:

```json
{
  "autoMode": {
    "enabled": true,
    "classifierModel": "anthropic/claude-haiku-4-5",
    "classifierReasoningLevel": "low",
    "allowInsideWorkingDirectory": true,
    "classifyReadOnlyTools": false,
    "deniedPaths": [
      "~/.ssh/*",
      "**/id_rsa",
      "**/id_ed25519",
      "**/*.pem",
      "~/.gnupg/*",
      "~/.aws/*",
      "~/.config/gh/*",
      "~/.config/op/*",
      "~/.config/gcloud/*",
      "~/.config/sops/*",
      "~/.pi/agent/auth.json",
      "~/.pi/agent/models-store.json",
      "~/.claude/.credentials.json"
    ],
    "log": { "enabled": true }
  }
}
```

`classifierModel` must be a provider you hold a credential for, and it is
resolved directly against the model registry rather than through the router.
Leaving it unset falls back to the live session model, which the router may
place on `llama-server` — a quantized local model adjudicating its own safety.
